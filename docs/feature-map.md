# 录播宝功能地图

首个可验收版本应让用户完成一件事：添加一个抖音直播间，离开任务页，开播后自动录制，下播后找到并播放本地文件。每个环节都要能看出当前状态，以及出错后可以做什么。

**基线**：2026-11-22 核对本地 StreamCap 快照，`config/version.json` 标记为 1.0.3、解析内核 4.0.10。以下盘点来自源码与默认配置，尚未逐项运行上游验证。录播宝当前已有 Tauri 前后端通信示例、主题 token 和独立官网。下表各项业务能力均为**待实现**；阶段表示建议顺序。实现后先标记「待验证」，满足验收条件再标记「已验证」。

## 用户从哪里进入

| 入口 | 用户能做什么 | StreamCap 参考入口 |
| --- | --- | --- |
| 任务列表 | 添加直播间、搜索主播、按平台和状态筛选、选择多项启停；查看未开播、正在检查、正在录制及失败原因 | `recordings_view.py`、`recording_filters.py` |
| 任务详情 | 编辑链接、画质、格式、分段和监控时间，处理重复链接提示，预览直播 | `recording_dialog.py`、`recording_card.py` |
| 录像文件 | 从保存目录逐级浏览、返回上级、预览本地录像；空目录和目录失效时给出明确反馈 | `storage_view.py`、`video_player.py` |
| 设置 | 配置录制默认值、输出命名、磁盘阈值、平台代理、Cookie、账号和通知渠道；恢复默认值 | `settings_view.py`、`config/default_settings.json` |
| 首页、帮助与关于 | 查看任务概况、公告、快捷操作、快捷键、版本及更新信息 | `home_view.py`、`help_dialog.py`、`about_view.py` |
| 托盘与退出 | 隐藏或恢复窗口，处理监控或录制中的退出请求，设置定时关机 | `app/lifecycle/`、`scheduled_shutdown.py` |

## 实现顺序与验收

| 阶段 | 功能范围 | 验收场景 |
| --- | --- | --- |
| 1 · 运行环境 | 启动时按架构检查 FFmpeg，缺失时后台下载，校验后安装；缓存复用、失败重试 | 首次下载时界面可用；校验失败的文件不会执行；已有可用版本时断网重启仍能加载组件 |
| 1 · 单任务监控 | 抖音链接解析、主播识别、任务增改删、轮询与手动启停。Rust 保存任务与监控意图 | 未开播时等待；连续两次检测到开播只启动一个录制进程；切换页面不中断，重启能恢复任务 |
| 1 · 录制与文件 | 选择目录、按可用画质获取流、写入 TS、显示录制状态；支持主动停止、下播收尾和文件定位 | 真实直播间产出可播放文件；主动停止后保持停止；网络中断与磁盘空间不足分别显示原因 |
| 2 · 多任务工作台 | 快手适配、批量添加与启停、重复项确认、状态与平台筛选、列表与网格、直播与录像预览 | 筛选后批量停止只影响选中任务；抖音和快手同时录制，单个任务失败不影响另一个 |
| 2 · 调度与桌面 | 定时监控、平台并发上限、后台托盘、退出收尾、系统通知和仅通知模式 | 在时间窗内启动检测，窗口外显示等待原因；托盘恢复后状态一致；仅通知模式开播时不创建录像 |
| 3 · 输出与后处理 | 音视频格式、FLV 直下、分段、目录及文件命名、时间字幕、转 MP4、原文件保留策略、录后脚本 | 分段文件可逐个播放；转码失败时保留原件；含中文的路径可定位；脚本按配置在录制完成后触发 |
| 3 · 设置与集成 | 平台认证与代理、通知模板和渠道、定时关机、中英文、主题、快捷键、统计、公告、更新检查 | 重启后设置生效；开播与下播分别触发已启用渠道；取消关机计划后不再执行 |

**状态判定**：任务是否启用监控、直播间是否开播、录制文件是否正在写入应分别记录。例如「已开播＋仅通知」与「已开播＋磁盘不足」都没有写文件，但前者是正常结果，后者需要用户处理。界面重开后以 Rust 返回的快照恢复状态。参考 `recording_status_model.py`、`record_manager.py` 和 `stream_manager.py`。

**默认行为对照**：上游默认每 180 秒轮询、每平台最多 3 个并发请求、输出 TS、每 1800 秒分段、录后转 MP4 并保留原件。后续逐项确定录播宝默认值；有意修改时，在对应功能项记录差异及验收结果。

## 平台与发行范围

- 逐平台验收。首批抖音、快手；随后覆盖虎牙、斗鱼、B站、小红书等国内平台，以及 TikTok、Twitch、YouTube 等海外平台。完整候选名单取自上游 README「已支持平台」与平台处理器。每个平台分别记录链接类型、是否需要凭据、离线识别、画质、真机录制结果和验证日期。当前已验证平台数为 **0**。
- 通知渠道逐一登记：桌面通知、钉钉、企业微信、飞书、Bark、ntfy、Server酱、Telegram、邮件。一个渠道测试通过只更新该渠道状态。
- Windows、macOS、Linux 分开验收组件安装、录制、预览和托盘。官网单独部署。上游的 Web 登录、浏览器刷新与 Docker 服务属于另一种运行方式，保留在范围清单中，是否提供远程管理端待决定。

上游项目与完整平台示例见 [StreamCap](https://github.com/ihmily/StreamCap)。录播宝的技术选型、FFmpeg 分发和验收规则见 [AGENTS.md](../AGENTS.md)。
