# 录播宝功能地图

首个可验收版本应让用户完成一件事：添加一个抖音直播间，离开任务页，开播后自动录制，下播后找到并播放本地文件。每个环节都要能看出当前状态，以及出错后可以做什么。

**基线**：2026-11-22 核对本地 StreamCap 快照（提交 `e1e8dbf`，2026-08-08），`config/version.json` 标记为 1.0.3、解析内核 4.0.10。以下盘点来自源码与默认配置，尚未逐项运行上游验证。录播宝当前已有 React 应用外壳（侧栏、四个占位页、状态栏）、主题 token 和独立官网。阶段表示建议顺序，「进度」列记录待实现、开发中、已实现待验证和已验证；实现后先标记「已实现待验证」，满足验收条件再标记「已验证」。

## 上线范围（0.1.0 公开测试版）

0.1.0 是首个公开发布的版本。下列各项全部达到「已验证」后才发布；不在清单内的能力留到后续版本，范围清单继续保留。

| 方面 | 上线要求 | 验收方式 |
| --- | --- | --- |
| 平台 | 抖音、快手：上游 README 列出的链接形式都能添加；检测开播、自动录制、下播收尾 | 每个平台用真实直播间完成一次「开播自动录 → 下播收尾 → 文件可播放」 |
| 直播间 | 任务表（七种状态、排序、按平台和状态筛选、搜索、多选批量启停和删除）；添加对话框（识别链接、重复提示）；编辑；右侧详情（三条状态、最近动态、打开文件夹） | 浏览器假数据下逐项操作；真实应用中添加、暂停、删除各一次 |
| 调度 | 按检测间隔轮询、每平台并发上限、失败退避重试、仅通知模式、手动停止后保持停止、断流后重新检测 | 本地样本流可重复测试；真实直播间验证一次 |
| 录像库与动态 | 按目录浏览录像、返回上级、用系统播放器打开、在文件夹中显示；动态按时间列出、按任务和类型筛选 | 含中文路径；目录不存在时有说明；重启后动态仍在 |
| 设置 | 保存目录、检测间隔、默认画质、格式与分段、磁盘阈值、录后转 MP4、代理、各平台 Cookie、FFmpeg 组件（状态、重新校验、重试）、关于（版本、许可证、第三方声明） | 修改后重启仍生效；非法值有提示 |
| 输出 | TS 分段录制；录后转 MP4，默认保留原件；转码失败保留原件 | 转出的 MP4 可播放 |
| 桌面行为 | 关闭窗口隐藏到托盘、托盘菜单；有录制时退出先确认并正常收尾；开播、录制失败的系统通知；单实例 | 托盘恢复后状态一致；退出后没有残留 ffmpeg |
| Linux 命令行（无界面） | 独立的命令行程序，不依赖 Tauri、GTK 或 WebKit，复用同一套核心逻辑：后台常驻监控并自动录制；用子命令添加、查看、暂停、删除直播间，停止录制，查看和修改设置；FFmpeg 自动下载或指定系统 ffmpeg；日志输出到终端；收到 SIGINT、SIGTERM 时正常收尾；提供 systemd 服务示例。Docker 镜像：推送到 GHCR，amd64、arm64 多架构，内置已校验的 FFmpeg，数据和录像挂载到卷，时区可配置，`docker stop` 时正常收尾；附 `docker compose` 示例 | 在没有图形环境的 Linux（CI 或容器）中跑通「添加 → 开播自动录 → 停止 → 文件可播放」；x64、arm64 各打一个包；镜像在 CI 中构建，并用同样流程验证一次 |
| 发布 | GitHub Actions 在 Windows、macOS、Linux 上跑测试；打包 Windows 安装包、macOS（arm64、x64）、Linux（AppImage、deb）；应用图标；版本号。GitHub Release 由人工发布后，Actions 把安装包上传到 xiaofany.com 分发平台（R2，dl.xiaofany.cn）。官网 lubobao.xiaofany.com 部署在国内备案服务器，页脚显示备案号；下载区读取 xiaofany.com 的版本接口，下载按钮走 `xiaofany.com/dl/lubobao/…`，GitHub Releases 作为备用。macOS 只做 ad-hoc 签名，官网提供 `curl … install.sh \| sh` 一键安装（校验 SHA-256），下载页和 Release 说明写清首次打开步骤 | Windows 实机安装、运行全流程；macOS、Linux 由 CI 构建和测试，实机验收待有设备；安装脚本在 CI 的 macOS 上跑通一次 |
| 自动更新 | 用 `tauri-plugin-updater` 做应用内自动更新：启动时和「关于」里检查 xiaofany.com 的 Tauri 升级接口，显示版本和更新说明，下载时显示进度，校验更新签名后安装并重启；有录制时先确认，按退出流程收尾后再安装。更新签名私钥只存在 GitHub Secrets 里。deb 安装的用户如果插件不支持，就提示手动下载 | 从旧版本升级到新版本：Windows 实机验证一次，macOS、Linux AppImage 待有设备；签名不符时拒绝安装；没有新版本时提示已是最新 |

暂不包含：其他平台、桌面通知以外的通知渠道、定时关机、英文界面、统计与公告、录后脚本、时间字幕、应用内播放器、Web 远程管理、代码签名（Windows SmartScreen 和 macOS Gatekeeper 会提示未签名，需购买证书后加入）。

**状态判定**：任务是否启用监控、直播间是否开播、录制文件是否正在写入应分别记录。例如「已开播＋仅通知」与「已开播＋磁盘不足」都没有写文件，但前者是正常结果，后者需要用户处理。界面重开后以 Rust 返回的快照恢复状态。参考 `recording_status_model.py`、`record_manager.py` 和 `stream_manager.py`。

**默认行为对照**：上游默认每 180 秒轮询、每平台最多 3 个并发请求、输出 TS、每 1800 秒分段、录后转 MP4 并保留原件。后续逐项确定录播宝默认值；有意修改时，在对应功能项记录差异及验收结果。

**有意差异 · FFmpeg 获取**：上游在 Windows 上从蓝奏云分享链接下载压缩包，在 macOS 和 Linux 上调用 `brew`、`yum` 或 `apt` 安装，均不校验文件（`app/scripts/ffmpeg_install.py`）。录播宝改为下载公用 npm 包 `@seankit/ffmpeg` 中当前平台的包（FFmpeg 9.0.2 GPL 构建，只取 `ffmpeg`），按固定 SHA-256 校验后安装。

**有意差异 · 抖音解析**（参考 StreamGet v4.0.10，提交 `e57e548`）：
- 取流请求头只带 User-Agent 和 Referer，用户 Cookie 不发给视频 CDN；上游取流时不带请求头，检测时会把用户 Cookie 发给 CDN。
- 接口状态 10011（「Request params error」附「当前服务繁忙」）按可重试处理，不判为链接无效：不存在的抖音号与服务繁忙返回完全相同，无法区分。4001038 仍判为直播间不存在。
- 接口缺少原画地址时跳过原画、继续使用其他档位，上游会报错。
- 网页主页链接直接从链接中取 `sec_uid`，省去上游的第一次请求，结果相同。
- 同一主播的直播间链接和主页链接可能得到不同的房间标识，按 `anchor_id`（`sec_uid`）去重。

**有意差异 · 快手解析**（参考 StreamGet v4.0.10 `KwaiLiveStream`）：
- 先完整解析页面状态（把 JavaScript `undefined` 换成 `null`），失败时退回上游只截取 `liveStream` 片段的做法。上游的正则截断在 `errorType` 之前，会把所有错误都报成「IP 被封」。
- 「错误代码22」和空页面无法与限流区分，按可重试处理；登录提示判为需要登录，验证码和「太频繁」判为限流，不存在、封禁、注销判为链接无效。
- 用户 Cookie 只用于用户信息接口的预检；该接口返回验证码或无法识别时退回房间页，上游会直接失败。房间页和取流都不带 Cookie。
- 录制前对选中的 FLV 做一次 HEAD 探测，连接失败时按抖音的规则换档；上游对快手不做探测。
- 缺少地址的画质档位会跳过，不影响其他档位。
- 暂不支持 `v.kuaishou.com` 等分享短链：上游只识别 `live.kuaishou.com/u/` 链接，也没有可供验证的真实短链。

## 平台与发行范围

- 逐平台验收。首批抖音、快手；随后覆盖虎牙、斗鱼、B站、小红书等国内平台，以及 TikTok、Twitch、YouTube 等海外平台。完整候选名单取自上游 README「已支持平台」与平台处理器。每个平台分别记录链接类型、是否需要凭据、离线识别、画质、真机录制结果和验证日期。当前已验证平台数为 **0**；完成真机录制并能播放后，平台才计为已验证。
- 通知渠道逐一登记：桌面通知、钉钉、企业微信、飞书、Bark、ntfy、Server酱、Telegram、邮件。一个渠道测试通过只更新该渠道状态。
- Windows、macOS、Linux 分开验收组件安装、录制、预览和托盘。官网单独部署。上游的 Web 登录、浏览器刷新与 Docker 服务属于另一种运行方式，保留在范围清单中，是否提供远程管理端待决定。
